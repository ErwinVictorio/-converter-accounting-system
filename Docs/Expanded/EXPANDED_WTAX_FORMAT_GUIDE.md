# Expanded WTAX Format Guide

This is the current format used by the app for Expanded Withholding Tax upload and DAT generation.

## Upload File Types Accepted

The Expanded WTAX upload accepts two Excel layouts.

## 1. System Expanded WTAX Export

Use this when uploading the Excel file generated by the current accounting system, like:

- `Docs/Expanded/EXPANDED WTAX.xlsx`

### Sheet Layout

- Header row: row 3
- Data starts: row 4
- The last `TOTAL:` row is ignored.
- The row `Date` must be inside the reporting month selected on the upload screen.

Required columns:

| Column | Header | Usage |
| --- | --- | --- |
| A | `No` | Optional source reference |
| B | `Date` | Used to validate selected reporting month |
| C | `Supplier Name` | Payee name |
| D | `TIN` | Payee TIN |
| E | `Reference` | Optional invoice/reference |
| F | `(1%)` | Tax withheld at 1% |
| G | `(2%)` | Tax withheld at 2% |
| H | `(5%)` | Tax withheld at 5% |
| I | `(10%)` | Tax withheld at 10% |
| J | `(15%)` | Tax withheld at 15% |
| K | `Total` | Summary amount from workbook |

### System Export Rules

- Every non-zero rate column becomes one Expanded WTAX row.
- The system export has tax withheld only, so the app computes:

```text
income_payment = tax_withheld / (rate / 100)
```

Example:

```text
Tax withheld at 1% = 1,340.13
Income payment = 1,340.13 / 0.01 = 134,013.00
```

Default ATC mapping for system export:

| Rate Column | Company ATC | Individual ATC |
| --- | --- | --- |
| `(1%)` | `WC158` | `WC158` |
| `(2%)` | `WC160` | `WC160` |
| `(5%)` | `WC100` | `WI010` |
| `(10%)` | `WC139` | `WI516` |
| `(15%)` | blank unless configured | blank unless configured |

If an ATC is blank after import, the row remains visible but DAT generation is blocked until the mapping is fixed.

### Payee Name Rules

- Names are normalized for BIR DAT output:
  - uppercase
  - commas removed
  - `&` becomes `AND`
  - unsupported punctuation removed
- Company-like names are stored as company payees.
- Names shaped like `SURNAME, FIRST MIDDLE` are treated as individual payees unless they look like company names.

Examples:

| Uploaded Name | Stored Type | DAT Name Fields |
| --- | --- | --- |
| `WORLD BEST IND'L. SALES, INC.` | company | company name only |
| `RAMORES, CARMEN` | individual | surname `RAMORES`, first name `CARMEN` |

## 2. BIR 1601EQ Schedule 1 Template

Use this when uploading the BIR template file, like:

- `Docs/Expanded/1601EQ_Schedule_1_template.xls`

### Sheet Layout

- Header row: row 1
- Data starts: row 2
- The selected upload month must match every row's `Reporting_Month`.

Required columns in order:

```text
Reporting_Month
Vendor_TIN
branchCode
companyName
surName
firstName
middleName
ATC
income_payment
ewt_rate
tax_amount
```

### BIR Template Rules

- The app reads `income_payment`, `ewt_rate`, `tax_amount`, and `ATC` exactly from the workbook.
- The app does not compute tax amount from income payment for this layout.
- If the uploaded tax amount does not match `income_payment x ewt_rate`, the row is imported but DAT generation is blocked.
- Fill either `companyName` or the individual name columns, not both.
- `branchCode` is padded to four digits.

## Generated DAT Filename

Expanded WTAX DAT generation is per withholding agent/company TIN and branch, per month.

Before upload and before DAT generation, select or enter:

- withholding agent/company TIN
- withholding agent/company branch code
- reporting month

The BIR AVS validator for 1601EQ expects this filename:

```text
{TIN}{BRANCH_CODE}{MMYYYY}1601EQ.DAT
```

For Fortress Steel:

```text
00879197600000420261601EQ.DAT
```

Meaning:

| Part | Value | Meaning |
| --- | --- | --- |
| `008791976` | company TIN |
| `0000` | branch code |
| `042026` | April 2026 |
| `1601EQ.DAT` | validator-required form suffix |

Do not use the old sample filename shape for validator upload:

```text
0087919760000043020261604E.DAT
```

That shape can trigger:

```text
Wrong Filename specified to be Validated (TINBCMMYYYY1601EQ.DAT)!
```

## Company/TIN Scoping

The company TIN in the filename and header is the withholding agent/company that files the return.

It is not the payee/vendor TIN.

The app stores the withholding agent on every Expanded WTAX row:

- `withholding_agent_tin`
- `withholding_agent_branch_code`
- `withholding_agent_name`

Re-upload behavior is scoped to:

- same withholding agent TIN
- same withholding agent branch code
- same reporting month

This means re-uploading Fortress Steel July 2026 does not delete another company's July 2026 rows.

DAT generation also filters by the selected withholding agent TIN and branch code. If two companies have Expanded WTAX rows in the same month, generate/download one DAT file per company.

## Generated DAT Body Format

The filename and the body must both be 1601EQ/QAP.

The old sample file:

- `Docs/Expanded/0087919760000123120251604E.dat`

is useful only as sample payee data. It is an annual 1604E body, so submitting that body to the 1601EQ validator causes errors like:

```text
Invalid Type of Alpha List. Value must be HQAP.
Invalid Form Type Code.
No Detail Record found in file!
```

### Header

```text
HQAP,H1601EQ,{WITHHOLDING_AGENT_TIN},{BRANCH_CODE},{MONTH_END_DATE},{WITHHOLDING_AGENT_NAME},{RDO_CODE}
```

Example:

```text
HQAP,H1601EQ,008791976,0000,04/30/2026,FORTRESS STEEL INC,045
```

### Detail

```text
D1,1601EQ,{WITHHOLDING_AGENT_TIN},{BRANCH_CODE},{MONTH_END_DATE},{SEQUENCE},{PAYEE_TIN},{PAYEE_BRANCH},{COMPANY_NAME},{SURNAME},{FIRST_NAME},{MIDDLE_NAME},{ATC},{INCOME_PAYMENT},{EWT_RATE},{TAX_AMOUNT}
```

Company example:

```text
D1,1601EQ,008791976,0000,04/30/2026,1,007086184,0000,"ACERSTEEL INDUSTRIAL SALES INC",,,,WC158,3682716.00,1.00,36827.16
```

Individual example:

```text
D1,1601EQ,008791976,0000,04/30/2026,2,220052738,0000,,"BANSIL","ANNIE",,WI516,5865.60,10.00,586.56
```

### Control Record

```text
C1,1601EQ,{WITHHOLDING_AGENT_TIN},{BRANCH_CODE},{MONTH_END_DATE},{TOTAL_INCOME_PAYMENT},{TOTAL_TAX_AMOUNT}
```

Example:

```text
C1,1601EQ,008791976,0000,04/30/2026,14284247.61,241326.68
```

## Consolidation Rule

Rows are consolidated before DAT generation.

Rows with the same:

- reporting month
- withholding agent TIN
- withholding agent branch code
- payee TIN
- ATC
- EWT rate

become one DAT detail line.

The app sums:

- `income_payment`
- `tax_withheld`

The first row in the group supplies the name and branch code.

## Common Validation Blockers

DAT generation is blocked when:

- payee TIN has fewer than 9 digits
- payee TIN is `000000000`
- branch code is blank
- ATC is blank or not configured
- ATC rate does not match row rate
- company row has no company name
- individual row has no surname or first name
- name fields contain comma or ampersand after import
- `tax_withheld` does not match `income_payment x rate`
